# Windows receipt layout and JPEG export

Receipt preview uses a centered logo/shop header, invoice/date, bordered customer/device/status and problem/diagnosis cards, item details, totals and emphasized balance. Print / Save JPEG / Close controls are outside the exported image. Zero-day warranty boilerplate is omitted. Customer phone and recorded repair device/problem/diagnosis/parts are included; no solution text is invented because there is no stored solution field. Parts are listed by name/quantity without exposing internal costs or adding costs again to the repair total. Original invoice settings and recorded currency/payment/change/refund arithmetic remain in use.

Save JPEG opens the operating-system save dialog and writes genuine JPEG bytes (quality 95) from a separate sandboxed 480px-wide renderer after fonts/images load. It captures the full receipt, including below the preview viewport; cancelling writes nothing. A 24,000px height limit rejects oversized output rather than silently clipping. An explicit resize handles hidden Chromium windows starting at 1x1; receipt-content height excludes excess page whitespace. JPEG has no app window, menu or action buttons. File names default to the invoice ID. Existing print settings still select A4/58mm/80mm via print CSS, independently of screen/JPEG layout.

The dedicated receipt preload exposes no generic app/database API. Its IPC handler validates the originating receipt main frame and an allowlist of jpeg/print/close actions; the current receipt permission is rechecked before saving. Receipt/customer fields are HTML escaped; restrictive CSP and bundled offline Myanmar/Thai fonts remain. Each preview uses its own temporary folder, removed on close.

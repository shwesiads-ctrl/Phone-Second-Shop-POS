# Signing a Windows release with a legitimate certificate

This build is **unsigned**. No publisher certificate, signing service or private key has been supplied, and no signing attempt is recorded. The cloud proxy's TLS trust files are unrelated to Windows publisher signing.

1. Obtain an organization-validated code-signing certificate from a trusted CA or enroll in a legitimate managed signing service. Use its supported hardware token/HSM or protected service identity. Keep private keys, passwords and signing access outside this repository, build logs and ordinary environment drafts. Follow the provider's issuance and authorization requirements.
2. Use a controlled Windows release runner with the Windows SDK `signtool.exe` and the provider's supported key-storage driver/service. Set the intended publisher metadata consistently. Sign the packaged application EXE and applicable DLLs **before** building its archive/installer. Electron Builder supports Windows signing configuration/custom signing hooks; configure the actual provider and fail the release if signing is required but unavailable.
3. This project uses custom `build/installer.nsi`. Signing only the outer installer does **not** sign the generated uninstaller. Integrate and validate an NSIS uninstaller-signing step (for example the supported `!uninstfinalize` mechanism with the organization's Windows signing command) or a reviewed equivalent before calling a release fully signed. This integration is pending; it must be tested with the real provider on Windows.
4. Sign the final NSIS installer after all content changes. Example with a legitimately installed signing certificate selected by its real thumbprint: `signtool sign /sha1 <actual-certificate-thumbprint> /fd SHA256 /tr <CA-provided-RFC3161-timestamp-URL> /td SHA256 <artifact.exe>`. The bracketed values are instructions to supply authorized provider data, not working credentials or a configured signing command. Token/cloud providers may require different arguments. Use a trusted timestamp so signature validity can survive certificate expiry.
5. Run `signtool verify /pa /all /v` on the app, installer and an installed uninstaller. Verify the expected publisher, chain and timestamp on a clean Windows machine; save verification output without credentials. Recompute SHA256 after signing. Never modify an artifact after signing.
6. Test clean installation, upgrade, uninstall/data retention and Defender/SmartScreen behavior with the final signed bytes. Signing does not guarantee SmartScreen reputation or remove the need for acceptance tests. Record actual warning text and OS build.

Until all those checks pass, distribute only as an explicitly unsigned test build and keep the signing checklist outstanding.
